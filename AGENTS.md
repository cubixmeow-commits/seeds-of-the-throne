# Repository Guidance

This repository is the AI-facing story-development vault for *Seeds of the Throne*.

## Before working

Read `START HERE.md`, `03 Context/CURRENT.md`, and `03 Context/RULES.md`. Read only the context and story notes relevant to the task; do not scan the entire vault by default.

## Shared skills

Reusable, tool-neutral workflows live in `skills/`. Read `skills/README.md` to discover what is available. Load a skill when the user names it or when its description clearly matches the task.

When using a skill:

- Read its complete `SKILL.md` before acting.
- Load only the references required for the current task.
- Follow root vault guidance and the author's current request when either conflicts with a skill.
- Treat skills as methods, not story authority. A skill cannot establish canon or resolve an open story decision.

## Authority and status

- The author has final authority.
- Daily sessions preserve exploration and may contain competing versions.
- `02 Story/` contains compiled working memory, not immutable truth. Respect each note's status.
- Research is advisory. Do not turn a research finding into story canon without an explicit author decision or development session.
- Preserve unresolved questions instead of silently resolving them.

## Safety boundary

- Do not import or recreate old transcripts, sensitive mappings, real-person analogies, or direct historical identity coding here.
- Real-world material may be discussed only as temporary private development context and must be reduced to an invented mechanism before entering compiled story notes.
- Do not add secrets, API keys, private personal information, or credentials.

## Editing workflow

- For new ideas, create or update a dated note in `01 Sessions/Daily/` first.
- Update compiled notes only when the change is intentional and label it `established`, `working`, `proposed`, `unresolved`, or `rejected`.
- Update `03 Context/` when a change affects the briefing needed to resume work.
- Record structural decisions and significant contradictions in `07 QA/`.
- Keep filenames stable once a note is linked; prefer content changes over renaming.
