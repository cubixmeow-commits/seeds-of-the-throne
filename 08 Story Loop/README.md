# Story Loop

The Story Loop is a human-readable, Obsidian-native system for completing the story before generating chapters.

## v0.1 target

A complete causal story map in which every load-bearing unit has:

- a known purpose;
- traceable source material;
- an entering state and resulting state change;
- causes, consequences, and dependencies;
- explicit missing decisions;
- a visible author-approval state.

## Folder roles

- [[08 Story Loop/STORY-MAP|STORY-MAP]] — the master causal backbone and work queue.
- `Units/` — one durable specification per Story Unit.
- `Brainstorms/` — prepared context and author questions, followed by extracted decisions.
- `Runs/` — chronological records of proposals, critiques, gates, revisions, and outcomes.
- `Templates/` — reusable Markdown forms.
- `Evaluations/` — recurring failure modes and later quality calibration.

## Status vocabulary

Story completeness and authority are separate.

**Completeness:** `missing`, `partial`, `testable`, `integrated`, `blocked`.

**Authority:** `established`, `working`, `proposed`, `unresolved`, `rejected`.

An `established` idea can still be structurally `partial`. A polished proposal can still be `proposed` and therefore non-canon.

## Completion pressure

Every run must be classified as one of:

1. `close-gap`
2. `strengthen-structure`
3. `new-expansion`

Choose `close-gap` by default. New expansion needs a clear reason that it advances story completion.

## Phase boundary

Version 0.1 ends at story architecture. Scene design, drafting, and prose evaluation are later phases. The existing prose skill may be used only after a unit or sequence has cleared the story-structure gates.
